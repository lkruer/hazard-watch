Bias ablation — how much of the score is real?

COOLR is report-derived, so labels cluster where roads and people are. The first build sampled background points uniformly across the region, which filled the negatives with remote steep wilderness nobody reports on — the model learned steep = no landslide and ranked the Columbia Gorge (44°) below a flat valley floor. Switching to target-group background sampling (anchored on real events, so observer effort cancels) cut the elevation mismatch between classes from −1.27 to −0.48 standardised, and dropped low-elevation enrichment from 5.1× to 2.1×. Headline PR-AUC fell 0.71 → 0.57 — the model got better; the 0.71 was substantially measuring where roads are.

Dropping the percentile features asks whether rainfall has to be judged against each cell's own record, or whether raw millimetres would do. Percentiles alone nearly match the full set; absolute millimetres alone lose 9% — which is the brief's “never an absolute threshold” rule, measured.

Elevation and landscape position still carry ~32% of the susceptibility score between them. TPI is partly real physics (failures initiate on convergent slopes), so this is not all bias — but read that score as relative within this region, not an absolute probability. Out-of-fold, observed landslide rate rises monotonically with slope, 0.075 at 0–2° to 0.287 at 30–66°, and the model tracks it.

Prospective hindcast — replaying 2016–2024

Model frozen on data through 2015 (training, tuning, calibration, threshold), then run over every day at every cell: 302,496 cell-days, 196 reported event-days — base rate 0.00065, the number the 1:4 training set hides. The training-set operating threshold alarmed on 39% of ALL days (a ~500× base-rate trap); production thresholds now come from the daily grid itself (serve/thresholds.json: alarm budgets of 2/5/10% of days).

Reported events caught (±1 day) vs alarm budget, 2016–2024. The rain rule is one feature — precip_3d_pctl_seasonal — with a threshold.

The curve flattens near 55–60%: roughly a third of reported slides fall on unremarkable-rain days (human-triggered, snowmelt, mis-dated) — a ceiling for any rainfall-only trigger. FAR stays >99% at these budgets because reported events are rare-in-time: an alarm means “conditions dangerous”, not “a slide will be reported”.

External check — NASA global susceptibility map

Sampled Stanley & Kirschbaum’s global map (~1 km, classes 1–5, live on the same NASA server) at all 5,352 of our points. On identical labels: ours PR-AUC 0.576 (ROC 0.823) vs global map 0.258 (ROC 0.667). Our mean score rises monotonically with their class (0.05 → 0.12 → 0.17 → 0.23 → 0.22) — the two maps agree about which terrain is dangerous; ours adds 30 m resolution. Caveat: our labels share the reporting process our model was fit to, so read this as “sane and locally sharper”, not “beats NASA globally”.

Transfer test — Myanmar satellite inventory (bias-free labels)

The Chin/Rakhine inventory is satellite-mapped — every visible failure digitised, no roads-and-reporters filter. Scoring 12,000 Myanmar points with the terrain model trained only in the Pacific Northwest went badly — and every rescue failed:

Why: 57–63% of Myanmar terrain lies beyond the PNW’s 90th percentile in roughness, relief and elevation — the trees saturate outside their training support, and the discriminating relationships are regime-specific. The features work there (local model 0.742) but the learned weighting does not carry. Conclusion: regional models where labels exist; slope-heuristic or NASA’s global map elsewhere; never ship a trained susceptibility model outside its region without local validation. This is why v1’s regional scope was the right scope — and why NASA’s global product is a heuristic, not a trained model.

Blockers

  • okSmart App Control blocker resolved

    Windows Smart App Control was enforcing and refused to load unsigned compiled extensions -- every binary wheel on PyPI. Turned off by the machine owner; state now 0.

    Effect: pandas, scikit-learn, LightGBM, rasterio and numpy.random all import. No code changes needed.

  • warnOpen-Meteo hourly quota forced a source swap

    Open-Meteo prices a request by locations x variables x days; a 218-cell x 21-year pull exhausted the free hourly quota. Switched the trigger layer to NASA POWER, which has no practical rate limit and returned all 92 cells in under a minute.

    Effect: Rainfall grid is ~0.5 deg instead of ERA5-Land's 0.1 deg. Costs resolution, not validity -- case-crossover compares each cell against itself, so coarseness adds noise but cannot bias either class. Open-Meteo remains the upgrade path behind the same interface.

  • warnAlphaEarth embeddings not yet included

    The AlphaEarth distance-from-own-history feature specified in the brief needs Earth Engine authentication (Google Cloud project + OAuth), which is the account owner's to grant.

    Effect: v1 susceptibility uses terrain only. The feature slots in as one more column when EE access exists.
